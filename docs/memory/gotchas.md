# Gotchas

See [[architecture]].

- **`src/data/blog-posts.ts` is generated.** Do not edit it by hand; run `yarn fetch-blog`. The daily workflow commits it, so pull before pushing.
- **The routes file `routeTree.gen.ts` is generated** by TanStack Router.
- **`node_modules` is not installed in this checkout,** so the site has not been built or looked at since the 2026-11-02 changes.
- **`graphify.exe` is blocked on this machine;** use `python -m graphify update .`.
- **Project links and screenshots live in `src/components/pages/projects.tsx` and `src/assets/*.webp` (the six project screenshots are WebP)** (1843x1020 each). On 2026-11-05 Nebula's demo became `https://nebula-ai0.vercel.app/` and NotionCraft's `https://notioncraft-ai-silk.vercel.app/` (the older addresses came from accounts the author lost), and both screenshots were retaken from the live landing pages with headless Chromium (`--window-size=1843,1020 --virtual-time-budget=10000`). `vite build` rewrites the generated `src/routeTree.gen.ts`; revert it before committing. There are no tests, and `yarn install` needed about five minutes on a slow network. On 2026-11-11 the PortaGen screenshot (`src/assets/Portagen.webp`) was retaken from `https://porta-gen-eta.vercel.app/` the same way (Blue Hour landing page); its demo link in `projects.tsx` now points to that address (the GitHub link stays `Haruru0-0/PortaGen`).
- **Preview animations look slow in a background browser tab:** GSAP is throttled, so window opens and the page fade-in can seem to take seconds although the code uses 0.35s / 0.55s.
- **`shadcn add` from third-party registries (2026-11-12):** it added a bogus npm package `cn` and files that import from it (fixed to `@/lib/utils`; check new files for `from "cn"`), and it prompts before overwriting `ui/badge.tsx` and `ui/card.tsx` (it hangs without a TTY; move the originals aside and restore them). Installing new packages makes the running Vite dev server fail with "Failed to fetch dynamically imported module" until it is restarted.
- **Dev server and new packages:** after installing packages the Vite dev server may serve 504 "Outdated Optimize Dep" or stop; restart it (`portfolio-dev` in `.claude/launch.json`). The browser tool's right-click does not fire `contextmenu`; dispatch the event from the page to test the desktop menu. `@8bitcn/audio-settings` overwrites `ui/button`, `card`, `label`, `slider` and `retro.css`; back them up before installing it.
- **Glass in Firefox/Zen:** the CSS `.liquidGlass-*` layers only refract in Chromium. Use `GlassPanel` (`surface`) for panels that must look right in Zen; the WebGL path was checked only by forcing `renderer="webgl"` in a Chromium pane, not in Zen itself.
- **EXIF rotation when converting images:** `wallpaper.jpg` was stored sideways with an EXIF rotate tag; a plain Pillow `convert` dropped the tag and the wallpaper came out rotated. Use `ImageOps.exif_transpose` before saving (checked: it was the only affected file). Pillow reads animated WebP durations as 0 after saving; check the `ANMF` chunks to confirm timings.
- **Dock glass cost:** the magnifying dock resizes its GlassSurface panel every frame. In the in-app pane it measured about 50ms per frame against 33ms idle, before the resize throttle was added; it was not re-measured afterwards. If it stutters, keep the glass panel a fixed size while icons magnify.
- **Backdrop root:** a parent with `will-change` of `opacity`/`filter`, `opacity < 1`, a filter or a mask makes glass panels inside it see only that parent's content, not the wallpaper or windows behind. The achievement toast wrapper had `will-change: transform, opacity`; it was removed (also from the mobile pill). Check ancestors when a glass panel looks flat.
- **Scrollbars in Firefox/Zen:** only `scrollbar-width` (`thin`/`auto`) and `scrollbar-color` apply there, so the rounded gradient thumb is Chromium/Safari only (`styles.css` uses `auto` plus a faint track for Firefox). Windows overlay scrollbars can still look thin; a fully custom scrollbar everywhere would need a scroll component instead of native scrolling (not done).
- **`import.meta.glob` options:** Vite rejects a variable as the second argument ("Expected the second argument to be an object literal"), so the `eager`/`query`/`import` options are repeated inline in `src/lib/wallpapers.ts`.
- **Clipped rings in scroll areas:** a `ring` or box-shadow on a child is cut off by a parent with `overflow-y-auto` (or `overflow-hidden`). Give the scroll container padding and cancel it with a negative margin (`-m-1 p-1`), as in the lock screen picker (`LockScreenSwitcher.tsx`).
- **Wallpaper names are ids:** a wallpaper's file name (without extension) is both its label and its saved id. Renaming a file changes its label and makes any saved choice of the old name fall back to the set's default (`DEFAULT_IDS` in `src/lib/wallpapers.ts`), so update `DEFAULT_IDS` when renaming a default.
- **Menu selection marks:** shadcn radio and checkbox items keep `pl-8` for the check or dot drawn at the left edge. A class like `px-3` overrides it and the mark lands on the item's icon. `DesktopContextMenu.tsx` now wraps them in `GlassRadioItem` / `GlassCheckboxItem`: the left dot/tick is hidden, the checked row gets `bg-white/15` and a right-aligned check (like the palette and theme dropdowns). Reuse these in any new glass menu.
